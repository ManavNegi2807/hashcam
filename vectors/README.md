# Conformance vectors (`abb/1`)

**Status:** the vector sets listed below are `IMPLEMENTED` and `TESTED` by the
Python cross-check (`tests/contract/`). They are **not** yet checked by the Rust
core — `core/` does not exist (Step 2 of `docs/IMPLEMENTATION_PLAN.md`), so
`abb vectors check` cannot be run and no cross-language agreement is claimed.

These files are the frozen expectations for the parts of the protocol built
first (`DESIGN.md` 20.1 item 1): canonical JSON, hashing and domain separation,
the Merkle tree with its proofs, checkpoints, and the global log of run roots.

## Files

| File | What it pins | Protocol |
|---|---|---|
| `jcs/canonical.json` | Exact canonical text and its SHA-256 for 11 values | 3.1 |
| `jcs/invalid.json` | 15 inputs a conforming parser must reject, each with a stable reason | 3.2, 3.3 |
| `hashing/domain_tags.json` | All 9 domain tags over one shared input, plus the untagged artifact digest | 4, D-03 |
| `hashing/tree_hashes.json` | Leaf prefix `0x00`, node prefix `0x01`, empty tree | 8 |
| `merkle/roots.json` | Tree hash for sizes 0,1,2,3,4,5,7,8,9,15,16,17 | 8 |
| `merkle/inclusion.json` | Audit paths for the first, middle and last leaf of every size | 8 |
| `merkle/consistency.json` | Consistency proofs between 27 size pairs | 8 |
| `merkle/malformed.json` | 7 proofs that must be rejected | 8 |
| `checkpoint/checkpoints.json` | Genesis, extension, idempotent replay, regression, fork, bad genesis, bad signature, wrong key role | 10 |
| `global/global_log.json` | Run-root records 1..5, global roots, global checkpoint, deleted run (TS-11), altered root (TS-12), injected root | 8.5, D-10 |
| `keys/test_keys.json` | Public test keys with roles and failure domains | 10.5 |

## Leaf data

Every Merkle vector builds its tree from `abb1-test-leaf-<i>` (ASCII, `i` from
0), so any implementation can rebuild the tree without trusting these files.
Global-log leaves are `"ABB1-RUNROOT" || 0x00 || JCS(record)`.

## Test keys: public, reproducible, worthless

`keys/test_keys.json` holds **public keys only**. The matching private seeds are
`SHA-256` of the labels in `tools/generate.py` (for example
`SHA-256("abb/1 test key v1 signer")`), so anyone can rebuild the key pairs.
That is deliberate — vectors must be reproducible — and it means these keys
provide **no security whatsoever**. They are test-only and must never be used
anywhere else (`TESTING.md` section 16). Real keys are generated by
`abb keygen`, kept in `secrets/`, and never committed.

## Regenerating

```bash
python vectors/tools/generate.py
```

Deterministic: the same code produces the same bytes, so a diff after
regeneration is a real change. A frozen vector is not edited to make a test
pass (`AGENTS.md` 3.23, 3.24). Changing canonical bytes, tags, tree rules or the
checkpoint layout needs a new decision, new vectors and a `protocol_version`
bump (`PROTOCOL.md` 18).

## `tools/` is not production code

`tools/jcs_ref.py` and `tools/merkle_ref.py` are the one permitted second
implementation of the cryptographic rules: the test-vector cross-check
(`AGENTS.md` 3.10). No service, adapter or signer may import them. The Rust core
in `core/` is what ships, and it must reproduce every expectation here.
