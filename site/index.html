The telemetry bus

Every agent action rides the same four stops, in this order. Click a stop (or press Enter on it) to read, in plain words, a real sample made in your browser a moment ago. The raw record is behind "Technical details".

1. SHA-256 Chain

Computing a real sample…

This sample uses the sandbox's simplified chain so every step is visible. Real receipts hash canonical JSON with domain tags into a Merkle tree and are checked by the Rust verifier.

One action, four steps

  1. 1 Record
  2. 2 Decide
  3. 3 Limit
  4. 4 Sign

  1. The agent acts. HashCam writes it down.

    Every action becomes an event. Each event carries the SHA-256 of the event before it, so changing anything that already happened changes its hash, and every hash after it.

  2. A fixed rule decides first.

    Before anything is sent, a deterministic policy answers allow, deny or hold. Same input, same answer, every time. No model gets a vote: machine-learning scores can only make a decision stricter.

  3. Money is fake, limits are real.

    Payments run against a local mock gateway, so no real money ever moves. Spending still has tiers: small amounts pass, larger ones wait for a person, and anything over the cap is refused even if someone clicks approve.

  4. A person signs. Anyone can check.

    The approval card shows who, what and where. Your passkey unlocks a signature over exactly that text. The sealed receipt then verifies offline with abb verify: valid means the record has not changed, nothing more.

Attach HashCam to an agent

Browser agents

BUILT

Claude in Chrome, Comet, browser-use, or you, in Chrome or Edge.

  1. Start the recorder: python tools/recorder.py --dsn …
  2. Load the extension/ folder (Developer mode, Load unpacked).
  3. Open its side panel, pair, register your passkey.
  4. Open the agent's tab, set the passport, press Record this tab.

MCP agents

PLANNED

Claude Code, Cursor, Claude Desktop.

An MCP proxy that sends every tool call through the same gateway and ledger. Not built yet.

Custom agents

BUILT

Your own agent reports each step to the local recorder API.

  1. POST /sessions: task, agent name, passport.
  2. POST /sessions/{id}/events: navigate, form_submit, download, secret.
  3. POST /sessions/{id}/stop: seals the receipt.

Full examples are in the console that ships with the repo.

Quickstart

About 30 seconds once the prerequisites are in place (Rust build of abb, a PostgreSQL you can create databases on). First-time setup takes longer: see the README.

git clone https://github.com/ManavNegi2807/hashcam.git && cd hashcam
pip install -r requirements.txt
python tools/recorder.py --dsn postgresql://abb@127.0.0.1:5432/postgres

No server, no network: the verifier reads the receipt and the public key manifest, nothing else. Exit code 0 means VALID, 1 means INVALID.

abb verify run.abbreceipt --keys run.abbreceipt.keys.json --profile LOCAL_ONLY

The Gatekeeper Sandbox exports a self-contained .html receipt that re-checks itself offline in any browser. (The real recorder exports .abbreceipt files, checked with abb verify or the receipt checker below.) You can also just double-click site/sandbox.html.

python -m http.server 8000 --directory site
# then open http://localhost:8000/sandbox.html, run the test flights,
# sign the gate, and press "Export Verified Receipt (.html)"
